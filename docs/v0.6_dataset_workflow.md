# GaiaLab Naija Dataset v0.6 Workflow

GaiaLab Naija Dataset v0.6 is a 200-record, openly licensed development draft for
Nigerian-context assistant behaviour. It is not a production corpus and has not
completed independent Nigerian cultural or domain review. No model is trained by
this workflow.

The examples cover banking, healthcare, government services, education,
agriculture, travel, technology support, small business, Nigerian Pidgin, and
business writing. Nigerian English and Nigerian Pidgin are treated as distinct,
internally varied language contexts. Review by Nigerian speakers, small-business
owners, and relevant domain professionals is required before publication or
training.

## Source contract

The permanent source files are the ten CSV files under `data/v0.6/examples/`.
Every file has exactly these columns:

```text
id,category,risk_level,user,assistant,system,source,status,review_notes
```

Allowed risk levels are `low`, `medium`, and `high`. IDs and normalized user
prompts must be unique across all ten files. User, assistant, system, source, and
status values cannot be empty. All current rows are synthetic CC0-1.0 GaiaLab
drafts; the generated JSONL records make that licence explicit.

Do not edit a source row in place after it has been reviewed or used. Add a new
row with a new ID, mark superseded material in a review process, and retain the
old row so the history is auditable. The scripts never write to the CSV files.
Keep proposed edits in version control and preserve each prior version.

## Generated records

The builder converts each CSV row into Qwen-compatible chat messages:

```json
{
  "id": "v06-example-001",
  "category": "example",
  "risk_level": "low",
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "source": "synthetic",
  "license": "CC0-1.0",
  "status": "draft",
  "review_notes": "..."
}
```

Generated JSONL writes are atomic. Before an existing JSONL is replaced, its
complete previous contents are copied to `data/v0.6/backups/` with a unique UTC
timestamp. Backups are never reused or silently overwritten.

The split is deterministic. Records are grouped by both category and risk level,
ranked with SHA-256 using the fixed seed `gaialab-naija-v0.6`, and assigned to
validation at the requested fraction. A multi-record stratum always retains at
least one training record and receives at least one validation record. A
singleton stratum remains in training.

## Run the workflow

From the repository root, use the Python 3.11 interpreter available in your
environment:

```bash
python3 scripts/pipeline_v06.py
```

On systems where Python 3.11 is exposed as `python`, the equivalent is:

```bash
python scripts/pipeline_v06.py
```

The fail-fast order is:

1. Validate all CSV inputs and build `v0.6_all.jsonl` plus the manifest.
2. Create the deterministic training and validation splits.
3. Validate that generated records exactly match the CSV sources and that the
   two splits are disjoint and complete.
4. Generate descriptive statistics.

Any non-zero step stops the pipeline immediately. A successful run creates:

```text
data/v0.6/generated/v0.6_all.jsonl
data/v0.6/generated/v0.6_training.jsonl
data/v0.6/generated/v0.6_validation.jsonl
data/v0.6/generated/dataset_manifest.json
data/v0.6/generated/dataset_statistics.json
data/v0.6/generated/validation_report.json
```

Individual steps can also be run with their corresponding scripts. Use
`python3 scripts/validate_v06_dataset.py --source-only` to inspect CSV sources
before generated outputs exist.

## Review and safety

The automated checks establish structure, provenance presence, duplication
status, deterministic splitting, and output consistency. They do not establish
medical, financial, legal, government, agricultural, cybersecurity, or cultural
correctness.

High-risk drafts direct users to appropriate qualified human or official support
and avoid diagnosis, guarantees, current fees, live schedules, or definitive
legal claims. Before any future training:

- obtain documented review from Nigerian speakers across more than one region;
- involve Nigerian small-business owners;
- have relevant professionals review high-risk domain examples;
- record review outcomes without deleting rejected or superseded source rows;
- keep evaluation prompts separate from these training sources; and
- run the dataset validator and complete test suite.

## Verification

Run:

```bash
python3 -m src.validate_dataset data/gaialab_naija_v0.1.jsonl
python3 -m pytest
python3 scripts/pipeline_v06.py
```

The first command validates the repository's existing default dataset contract;
the v0.6-specific structural and split checks run in the pipeline. Do not commit
model weights, adapters, checkpoints, logs, sensitive prompts, or credentials.
